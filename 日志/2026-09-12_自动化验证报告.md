## ⚠️ 已识别问题

### P001 | 架构违反 | 🔴 高严重度

**标题**: 外部依赖与设计声明不符

**问题描述**:
项目 README.md 明确声称『无外部依赖，全部基于 Python 标准库』。设计文档中也强调『无外部依赖』是保证离线可运行性的关键。然而，代码中发现了以下三类外部依赖：

```python
# agent/multiagent/health_monitor.py
from prometheus_client import Gauge, Histogram, CollectorRegistry, REGISTRY, generate_latest
from prometheus_client import start_http_server

# agent/multiagent/{api,loader,router}.py
import yaml

# agent/core/models.py
from urllib.parse import urljoin
from urllib.request import urlopen
```

这直接违反了项目的设计约束。

**具体影响**:
- `health_monitor.py` (62 行) 及其测试文件 (`test_health_monitor.py`) 因缺失 `prometheus_client` 无法导入，被迫排除于测试套件外
- 健康监控功能完全无法验证（0% 覆盖率）
- 项目无法离线运行和测试（缺失 yaml、urllib 时）

**根本原因**:
代码实现人员在开发功能时，为了便利引入了外部库，但未与设计保持同步。没有在 `requirements.txt` 或 `setup.py` 中显式声明这些依赖。

**可行性**: ✅ 可以修复
- prometheus_client: 改为条件导入 (try/except)，无可用时使用 mock 实现
- yaml: 改为使用 json 或内置配置格式
- urllib: 改为 socket + HTTP 手工实现（仅用于模型路由，可用简单 HTTP 客户端）

当前测试执行必须使用 `--ignore=agent/multiagent/tests/test_health_monitor.py` 来规避导入错误。这意味着多 Agent 系统的健康监控功能完全未被验证。

**具体影响**:

- 无法验证健康状态检测逻辑
- 集群故障时，节点健康监控可能失败，导致集群无法自动转移

```python
try:

    HAS_PROMETHEUS = False
    # 提供 mock 实现
```

#### 关键性能指标 (KPI)

| 指标 | 基准值 | 告警阈值 | 衡量方法 |
|------|--------|---------|---------|
| Agent 启动时间 | < 100ms | > 150ms | 首次初始化到就绪 |

| 消息吞吐量 | ≥ 1000 msg/s | < 800 msg/s | 每秒处理消息数 |

#### 实现方案

   ```bash
   pip install pytest-benchmark
   ```

   - `agent/benchmark/test_startup_time.py` - Agent 启动性能

   - `agent/benchmark/test_memory_usage.py` - 内存占用
   - `agent/benchmark/test_throughput.py` - 消息吞吐量

3. **记录基准数据**
   ```bash
   python3 -m pytest agent/benchmark/ --benchmark-json=benchmark_baseline.json
   ```

   ```bash
   # 新版本 vs 基准线

   # 如果回归 > 5%，告警并中断构建
   ```
